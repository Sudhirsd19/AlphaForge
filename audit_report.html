2. Critical & High-Priority Findings

SEC-01: Plain-Text Credentials in .env File Critical

The .env file contains highly sensitive credentials in plain text: Upstox API key, API secret, mobile number, PIN, TOTP secret key, and a JWT access token. While .gitignore correctly excludes .env and git history shows it was never committed, these credentials sit unprotected on disk with no encryption at rest.

The TOTP secret key (UPSTOX_TOTP_KEY) is particularly dangerous — it allows generating valid 2FA codes indefinitely, meaning a single file leak compromises the entire brokerage account.

Recommendation: Migrate secrets to OS keyring (Windows Credential Manager), encrypted vault, or at minimum set file permissions to owner-only (chmod 600). Consider rotating all credentials since they are now visible in this audit context.

SEC-02: 181 Uncommitted Changed Files (Whitespace-Only) Critical

There are 181 modified files shown by git status, spanning every subsystem — source, tests, docs, golden fixtures, and pyproject.toml. However, git diff -w (ignore whitespace) produces zero output, meaning all 181 changes are whitespace/line-ending modifications only (likely CRLF ↔ LF conversion on Windows).

This makes git diff and git blame nearly useless for code review, and masks any real future changes in noise. It also means the working tree does NOT match the Phase 18 certified commit (0a74822).

Recommendation: Add * text=auto eol=lf to a .gitattributes file, run git add --renormalize ., and commit. This permanently fixes cross-platform line ending issues.

SEC-03: Dashboard Server Binds to Localhost Without Authentication High

The 2,273-line dashboard_server.py runs on localhost:8080 using Python's built-in http.server. While binding to localhost limits network exposure, there is no authentication, no CORS restrictions, and direct access to kill switch controls, order routing, and market data APIs. Any local process or browser tab can interact with it.

Recommendation: Add HMAC-based session tokens (the hmac and secrets imports are present but verify they gate all mutable endpoints), and consider binding to 127.0.0.1 explicitly with a CSRF token on state-changing operations.

CODE-01: Large Monolithic Script Files High

dashboard_server.py (2,273 lines), dashboard.html (194K), and run_upstox_paper_session.py (33K) are extremely large single files. These are difficult to test, review, and maintain. The server mixes HTTP routing, business logic, UI rendering, and broker integration in one file.

Recommendation: Refactor dashboard_server.py into a proper module with separated route handlers, data access layer, and template rendering. Extract dashboard.html into components.

SEC-04: ruff noqa Suppressions on Security-Sensitive Scripts Medium

Both refresh_upstox_token.py and dashboard_server.py use broad # ruff: noqa: S603, S607 suppressions, disabling bandit's subprocess security checks. The token refresh script calls systemctl via subprocess.run, and the dashboard server also uses subprocess. These are legitimate use cases but blanket suppression hides potential future issues.

Recommendation: Use line-level # noqa: S603 only on the specific subprocess calls rather than file-level blanket suppression.

4. Safety & Trading Controls Audit

Dual-Key Live Trading Protection Strong

Live trading requires both TRADING_MODE=LIVE and live_trading_enabled=True (dual opt-in). The SecurityConfig uses Pydantic frozen models with extra="forbid", preventing injection of unknown fields. Kill switch cannot be disabled — the validator raises SecurityConfigurationError if kill_switch_enabled=False is attempted. Risk controls, reconciliation gate, and startup gate are all non-relaxable.

Broker Guard Layer Strong

The DeploymentBrokerGuard unwraps decorator layers to identify the core broker, uses a 4-tier detection system (PaperBroker check → explicit capability attribute → class name heuristics → fail-closed default), and guarantees PAPER/SHADOW modes can never route to a live broker.

Shadow Execution Guard Strong

ShadowExecutionOnlyGuard independently checks live_trading_enabled context and blocks live execution. This provides defense-in-depth separate from the security config layer.

6. Testing Architecture Audit

Comprehensive Multi-Tier Test Suite Strong

TEST-01: No Coverage Reporting Configured Medium

While pytest-cov is listed as a dev dependency, the pytest configuration does not include --cov in addopts. There is no evidence of a coverage report or minimum coverage threshold enforcement. Without this, dead code and untested paths go undetected.

Recommendation: Add --cov=alphaforge --cov-report=term-missing --cov-fail-under=85 to pytest addopts.

TEST-02: scripts/ Directory Lacks Test Coverage Low

The scripts/ directory contains 10 operational scripts (13 files, ~430K total) including the critical dashboard server and paper trading session runner, but only test_upstox_paper_session_bridge.py and test_dashboard_server.py cover parts of them. The 2,273-line dashboard server likely has significant untested code paths.

7. Git & Repository Hygiene

GIT-01: Multiple Divergent Branches Medium

Active branches: master (current), main, agents/read-only-audit-report-generation, phase6-implementation-check. The existence of both master and main can cause confusion. Old feature branches should be cleaned up.

Recommendation: Consolidate to a single default branch, delete merged/stale branches.

GIT-02: No CI/CD Pipeline Detected Medium

No .github/workflows/, .gitlab-ci.yml, or equivalent CI configuration files were found. Tests, linting, and type-checking rely entirely on manual local execution. For a financial trading system, automated quality gates are essential.

Recommendation: Add a GitHub Actions workflow that runs pytest, ruff, and mypy on every push and PR.
